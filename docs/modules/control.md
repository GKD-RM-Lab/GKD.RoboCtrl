# Control 模块

路径：`include/ctrl/`、`src/ctrl/`。控制层组合设备状态和目标，不解析总线报文；具体协议留在 Device/IO。

## Robot 与初始化

Robot 通过底盘/云台工厂取得抽象接口，拥有主控制状态与可选第二发射实例。云台工厂可持有多个独立实例，分别绑定 IMU/电机。配置预检拒绝一个执行器绑定多个控制器；Robot 只使能实际绑定的执行器，未绑定配置电机保持禁用。

默认 `NoForce`。遥控双开关下且滚轮 `-660` 解锁后，有云台进入 `FinishInit`，仅允许受控云台回中，底盘/发射保持关闭；所有配置云台在明确零位、容差和连续稳定时间条件满足后转 `FollowGimbal`。无云台车型直接进入运动状态。解锁只响应新报文中的手势上升沿，失联后保持原手势不能自动解锁；键鼠位移每包消费一次。遥控失联退回 NoForce，失联/故障云台不能继续授权发射。未知机械零位不自动通过初始化。

`Search` 由明确自动瞄准输入且视觉失效策略启用时进入；`Idle/NotFollow` 作为控制接口状态保留，不宣称完整比赛决策自动机。所有长期任务在单线程 Asio 内主动等待，旧无限调参循环未进入启动路径。

## Motion 与 Chassis

`motion_control` 映射遥控/键鼠，选择手动/新鲜视觉目标，协调大 yaw/小头，处理导航、搜索、发射许可与遥测。云台坐标旋转、跟随 PID、停止自旋后的同向回中位于 Control。底盘设备只执行麦轮分解、统一比例限速和显式轮方向，不反向依赖云台/控制策略。

`wheel_directions` 按 LF/RF/LR/RR 排列，四车型明确 `[-1,1,-1,1]` 保持旧同坐标输入的最终电机目标。旋转量仍参与轮速合成，没有引入未经标定的几何长度。详情见 [运动迁移](motion-migration.md)。

## Gimbal 与输入来源

云台设备暴露姿态目标、相对机械角、有效性、回中、初始化状态和启停接口。DJI/M9025 可采用角度外环、补偿 IMU 角速度内环直接电流路径；J6006 使用固件原生 rad/s 速度模式，不能称为同一外部 IMU 内环。设备离线、故障、无效反馈或未标定回中会阻止有效输出。

视觉目标必须通过应用协议、来源和超时检查；无新鲜目标时禁止视觉开火，可按配置巡扫。视觉包里的旧模式字段不能解锁机器人。主/副发射机构只能获得各自云台的许可。导航使用同样的新鲜度边界，遥控失联仍具有最高优先级。见 [网络协议](network-control.md)。

## Shoot 与 Referee

`shoot` 先 init 绑定，再 start 周期协程。使用 `motor_base*`，辅助判断仍私有放在 `.cpp`，无独立 `shoot_logic.hpp`。摩擦轮按 m/s 斜坡控制；拨弹用输出轴 rad/s，保持旧 6/-2 的含义。NoForce/未使能、依赖离线或非有限反馈清输出；发射还受摩擦轮打开与就绪、对应云台许可、堵转暂停和可选裁判门约束。

三作战车型默认裁判门开启，分别检查 17/42 mm 弹量、比赛进行中、存活、发射电源与各报文独立新鲜度。Hero 正好到达就绪阈值可以发射，阈值必须大于零且不大于目标。热量预测、弹速闭环和单发节拍无可靠旧实现，不宣称已提供。UI 显示最终 `fire_allowed()`。见 [裁判与发射](referee.md)。

## Power

`power_manager` 已替代旧宏关闭骨架。motion 每周期收集新鲜裁判/超容状态，执行能量环、功率模型和按轮分配，并把绝对电流上限安装到实际轮电机；DJI 分组发送通过同一最终输出门读取，后续 PID 不会旁路上限。RLS 只在明确开启且有新测量时更新，默认关闭。

当前 35 W 是保守软件配置，模型系数由旧转子坐标代数换算而来，仍需功率计标定。滑行损耗大于预算时报告预算不可实现并抑制驱动力，不声称纯软件可消除损耗。见 [功率控制](power-control.md)。
