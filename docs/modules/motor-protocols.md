# 电机协议与超级电容

本页记录本次迁移新增的协议、可调用接口和软件验证边界。设备生命周期仍为 `construct/init → connect → start`，所有发送任务都在同一个 Asio 事件循环内周期让出。配置与主入口负责按依赖顺序调用这些阶段；构造和配置校验不访问 CAN。

## 统一目标和电流限幅

`motor_base::set()` 对当前三个驱动统一表示线速度 m/s；`set_angle_speed()` 表示输出轴角速度 rad/s。DJI 的两种速度模式分别用线速度或角速度反馈驱动配置的 PID；切换模式时清理 PID。拨弹应使用角速度入口，不能把旧 `6/-2 rad/s` 当成 m/s。

`set_current()` 表示驱动原始命令单位，**不表示 A**。DJI 和 M9025 支持此接口，可供使用 IMU 角速度反馈的云台内环直接下发输出；J6006 速度模式不支持，调用会明确抛出异常。J6006 的反馈 `torque()` 是 Nm，DJI/M9025 的同名历史访问器是原始电流计数；功率控制应使用 `current_feedback_raw()` 并配置比例系数，不能混用。

`requested_current()` 读取功率限制之前的请求；`set_output_scale()` 和 `set_current_limit()` 分别设置缩放与绝对电流上限。DJI 分组发送和 M9025 每次发送均执行：

```text
原始请求 → 比例缩放 → 绝对电流上限 → int16 安全范围 → enabled/online 门 → CAN 编码
```

因此两次功率分配之间 PID 请求突然增大也不能超过上一轮下发的绝对上限。非法浮点数、非法限幅、禁用或离线都输出零。`disable()` 清 PID 和待发输出，仍保持默认禁用、只使能实际绑定执行器的上层规则。

DJI 保留用户已有的本地 `dji_upload_pkg` 和字节解析实现，不重新引入通用电机报文结构。反馈回调仅更新物理量与在线时间；PID 在配置周期运行一次，避免同一反馈在回调与控制任务重复积分。`set_current()` 模式不会被电机速度 PID 覆盖。反馈 8 字节、8192 编码器计数、减速比与原实现一致，编码器超过有效范围不刷新在线状态；2 ms 离线阈值暂保留，仍需台架确认。输出轴速度带减速比，单圈编码器角度仍是电机侧角度，不能假设两者可直接积分互换。

## J6006

实现：`include/device/motor/j6006.h`、`src/device/motor/j6006.cpp`、`include/device/motor/protocol.hpp`。`find_motor("j6006", key)` 由 `device/motor/lookup.hpp` 解析，控制层无需反复访问具体注册表。

来源为旧工程实际未跟踪的 `J6006.hpp/.cc`，以及厂商[达妙控制协议 V1.4](https://github.com/dmBots/damiao-document/blob/master/%E8%B0%83%E8%AF%95%E5%8A%A9%E6%89%8B%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E%E4%B9%A6%EF%BC%88%E8%BE%BE%E5%A6%99%E9%A9%B1%E5%8A%A8%E6%8E%A7%E5%88%B6%E5%8D%8F%E8%AE%AE%EF%BC%89V1.4.pdf) 第 4.1、4.4–4.6 节。已核实速度模式命令是 `0x200 + id`、4 字节 IEEE754 小端 rad/s；旧工程发送 8 字节，本实现按厂商 DLC=4 修正。使能/失能使用同一控制 ID 的 8 字节特殊帧：前七字节 `FF`，末字节分别 `FC/FD`。

反馈在配置的 `master_id`（默认 0）接收，严格为 8 字节。首字节低 4 位用于区分电机，高 4 位是状态：0 失能、1 使能、8–E 故障。未知状态不作为心跳；已知故障保留遥测和在线状态，但命令归零。位置为 16 位，速度与力矩各为 12 位，分别映射到配置的 `±position_max`、`±velocity_max`、`±torque_max`。这些范围必须与驱动器参数一致；默认值保留旧源码的 12.5 rad、45 rad/s、20 Nm，不声称已经读回硬件验证。

`motor_base::faulted()` 与 `offline()` 分离：J6006 的有效故障报文仍能刷新通信心跳，但向控制层报告故障，不能据此继续发射或认为云台已准备好。零速度仍可能产生保持力矩；IMU 等依赖失效时，控制层应关闭驱动使能，而不把零速度当成零力矩。

配置提供 `direction`、`radius`、`max_speed`、`control_time`、`offline_timeout`。`id` 限制为 1–15，避免反馈低四位出现歧义。相同 `master_id` 可共享，但 CAN 总线与反馈低四位组合必须唯一。机械零位需要在这个位置映射下表示；旧把 J6006 原始编码器乘 `2π/65535` 的 M9025 系数不能直接保留。

启用请求由周期任务发送，收到状态 1 且在线后才允许非零速度；未连接时 `start()` 报错。禁用会清速度并下发失能。故障在本次软件使能期间锁定，只有显式禁用后重新启用才解除软件锁；不自动发送清故障或写零位报文。离线清除目标，恢复通信后也必须由控制层重新提交目标。初次启动与状态转换立即发送特殊帧，之后每 100 ms 重发期望使能状态。

J6006 使用驱动器内部速度环。它没有被伪装成 DJI 电流控制，不把旧“IMU 速度 PID 的输出再作为硬件速度”称为与电流内环等价。若需要在该轴使用外部 IMU 角速度电流内环，应另行确认 MIT 力矩模式、固件参数和力矩标定，再增加明确的 Nm 接口。

当前哨兵来源拓扑存在可证实的冲突：旧 `config_sentry.hpp:103/197` 将 DJI M3508 拨弹设为 `CAN_GIMBAL, id=1`，旧 `gimbal_sentry.cc:19` 同时将 J6006 大 yaw 设为相同总线和 ID。DJI 反馈和 J6006 速度命令因此都占用 `0x201`。未经实际总线/ID 确认不改写硬件常数；保留来源的 `configs/sentry.yaml` 应在语义预检拒绝该冲突。J6006 大 yaw 零位也保持 `yaw_zero_calibrated=false`。这两项是该配置的部署阻断，协议单测通过不解除它们。

## M9025

实现使用 snake_case 类型 `m9025`，兼容别名 `M9025` 不形成第二份驱动。它同样提供构造、连接、启动、周期速度 PID、直接原始电流输出、使能和禁用。

协议依据旧 `src/device/M9025.cc`：收发 ID 为 `0x140 + id`；发送 8 字节，首字节 `A0`，第 4/5 字节是有符号命令的小端表示。反馈严格检查长度与 `A0` 命令回显，温度在第 1 字节，电流在 2/3、速度在 4/5、编码器在 6/7。以前的新工程误用 DJI 大端布局和 `0x200+id` 的 TODO 零帧均已删除。

`encoder_counts_per_turn=65535` 仅继承旧配置常数。旧字段被命名为 `speed_rpm`，但没有可确认型号和固件版本的厂家协议；因此 `speed_rad_per_count` 必须显式给出正值，缺失会在语义预检和构造中拒绝。若使用旧名称的 RPM 解释，此值为 `2π/60`，这属于待台架核对的兼容配置，不是协议认证。编码器每圈计数限定在 1–65536；速度缩放上限保证 int16 全量程转换仍为有限数。`direction` 同时转换反馈和命令。示例不代表现有车型安装了 M9025。

`enable/disable` 是软件原始命令门，禁用或离线持续发送 `A0` 零输出；未臆造该固件的硬件使能命令或把 `A0` 偷换成另一厂商型号的 `A1`。PID 增益、原始命令到 A/Nm 的比例和实际固件响应仍需上机核对。

## 超级电容

实现：`device/super_cap.h`、`device/super_cap_protocol.hpp`、`src/device/super_cap.cpp`。单例 `init()` 只校验/保存配置，`connect()` 注册回调，`start()` 启动周期发送。反馈和命令 ID 默认为 `0x51/0x61`，可配置。反馈 8 字节逐字段按旧小端协议解析：错误码、float32 底盘功率 W、uint16 功率上限 W、uint8 能量；拒绝长度错误与非有限功率，只有有效反馈刷新 500 ms 在线计时。

`set(enable,power_limit)` 保存控制请求，功率限制不超过配置的 `max_power_limit`；发送任务默认每 50 ms 重发，包含启用位、功率限制和配置的 `buffer_target`（旧值 50）。控制请求超过 `command_timeout`（默认 100 ms）、设备离线或错误码非零时关闭使能；过期请求同时将功率上限归零，避免无人更新时无限重放非零命令。`sample_sequence()` 每个有效遥测递增，供 RLS 避免把同一测量重复当作独立样本。

功率模型、裁判功率限制、能量策略属于控制层，驱动不引用旧 `Robot_set`。旧超容启动原已注释；当前代码存在不构成旧实车功能已验证的证据。

## 验证范围

`tests/motor_protocol_tests.cpp` 的 `test_motor_protocols()` 覆盖 M9025 正负命令/反馈、短长帧与错误回显；J6006 位域端点、DLC4、特殊命令、状态/ID/长度、故障/失联/禁用门；电流饱和及功率绝对上限；超容小端 float、长度、NaN、发包及过期/失联/故障门。断言使用抛异常，不受 `NDEBUG` 弱化。

可独立编译运行该纯协议测试：

```sh
clang++ -std=c++23 -Wall -Wextra -pedantic -Iinclude -DROBOCTRL_MOTOR_PROTOCOL_TEST_MAIN tests/motor_protocol_tests.cpp -o /tmp/gkd-motor-protocol-tests
/tmp/gkd-motor-protocol-tests
```

本轮遵守用户“不执行 xmake”的最新要求。独立协议测试和直接 C++ 语法检查不代表 Linux 主目标构建，更不代表 CAN 实际收发、固件兼容、时序、PID、机械方向或实车安全已经验证。
