# 裁判协议、UI 与发射许可

路径：`include/device/referee/`、`src/device/referee/referee.cpp`、
`include/ctrl/shoot.h`、`src/ctrl/shoot.cpp`。

## 来源与边界

本次迁移以旧工程 `include/device/referee/protocol.hpp`、
`src/device/referee/referee_base.cc`、`referee.cc`、`src/device/UI.cc` 和
`src/shoot/shoot.cc` 的实际代码为来源。旧协议头自己标注需要逐年更新，但没有可核验的版本号；
UI 源码标注基于 RM2020 协议。新实现冻结这些已有布局，不宣称兼容某个更新赛季的裁判固件。

旧裁判/UI 启动被注释；旧 `shoot_heat` 恒为 true，不能把历史实现称为已验证的热量管理。
新模块提供可执行的协议、生命周期、显示和发射门，通过运行时配置接入；仍需与实际裁判固件、
客户端、串口和机器人做台架联调。**无硬件测试通过不等于比赛/实车通过。**

## 传输与生命周期

专用 `io::serial::info_type` 设置 `raw: true`。默认串口仍沿用 IMU/遥控的 `55 AA + key` 封装；
raw 模式直接分发每次读到的实际字节，并通过同一个异步写队列发送原始帧，禁止调用带 key 的发送。
裁判设备不拥有额外线程、阻塞串口或旧 `Robot_set`。

`device::referee` 是唯一服务，`init(info)` 保存配置，`connect()` 在已构造的 raw 串口注册回调，
`start()` 按 `ui_enabled` 启动周期显示协程。入口必须先完成 connect 再启动串口接收。
`info_type` 的字段直接用于运行时 YAML/JSON：

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `serial_name` | `referee` | 已声明的专用 raw 串口 key |
| `offline_timeout` | 1 秒 | 接收心跳与各类数据的有效期限 |
| `ui_enabled` | false | 是否允许发送 UI 图形 |
| `ui_period` | 100 毫秒 | UI 周期，必须至少 100 毫秒 |
| `ui_receiver_id` | 0 | 0 时按机器人 ID 推导操作手客户端；非 0 为显式目标 ID |

`configured()`、`offline()`、`data()`、`timeout()` 提供设备快照。只有通过帧校验且符合已知命令
长度/字段约束的数据才刷新在线时间。每一类状态有独立 `received_at`；新收到功率包不会使陈旧弹量
变得有效。CRC 合法的未知命令仍可通过 `on_frame()` 观察原始数据，但不会被当成已识别心跳。

## 帧、数据模型与校验

帧为 `A5 + payload_length:u16le + seq:u8 + CRC8 + cmd:u16le + payload + CRC16le`。
CRC8 使用反射多项式 `0x8c`、初值 `0xff`；CRC16 使用 `0x8408`、初值 `0xffff`，均无最终异或。
增量解析器支持任意拆包、粘包、前导噪声、坏 CRC 后重新找帧。payload 最大 256 字节；内部缓冲不随
任意长噪声增长。报文字段使用明确的移位/小端读取，不依赖 packed 结构、主机端序或 bitfield ABI。

| 命令 | payload 长度 | 模型 |
| --- | --- | --- |
| `0x0001` | 11 | 比赛类型/阶段、剩余秒、同步时间戳 |
| `0x0002` | 1 | 比赛结果 |
| `0x0003` | 32 | 16 个机器人/基地/前哨 HP 槽 |
| `0x0104` | 3 | 警告级别、机器人、次数 |
| `0x0201` | 13 | 身份、HP、冷却参数、底盘功率上限、三路电源许可 |
| `0x0202` | 16 | 缓冲能量、两路 17 mm 和一路 42 mm 热量 |
| `0x0203` | 12 | x/y/yaw，拒绝 NaN/Inf |
| `0x0207` | 7 | 弹种、发射器 ID、频率、弹速，拒绝无效浮点数 |
| `0x0208` | 6 | 17 mm/42 mm 剩余弹量及金币 |

源协议 `0x0202` 的前 8 字节命名为 reserved，不能将其擅自解释成实时功率、电压或电流。
功率管理使用已明确的功率上限/缓冲能量，以及超级电容提供的实测功率。
其他命令保留 CRC 合法原始帧观察接口，未建立其高层业务数据模型。

## UI 图元与状态

`graphic` 支持线、矩形、圆、椭圆、弧、数值和文字的共同字段。`encode_graphic()` 明确编码
3 字节名称和三个 32 位字段组，逐项检查宽度；名称采用配置给出的线序，不暗中倒序。
`encode_graphics()` 支持协议规定的 1/2/5/7 图元，`encode_text()` 支持不超过 30 字节并补零，
`encode_delete()` 支持按层或全删除。均封装为 `0x0301` 交互消息并计算两级 CRC。

`numeric_bits` 是显式数值位模式接口：旧 UI 浮点实现写入 IEEE754 位模式；不同赛季客户端可能要求
不同数值表示，调用者必须先核对客户端版本。内置状态显示使用几何图形，因此不依赖该不确定性。

控制层调用 `set_ui_status()`，周期显示从左到右的摩擦轮就绪、自瞄、自旋和发射许可四个圆标，
下方线段显示 0–100% 电容能量。绿色表示 true、黄色表示 false。首次得到可用的机器人/客户端地址、身份过期后恢复、地址改变，以及每 50 次有效刷新时发送新增
操作，其余使用修改操作，恢复客户端显示。比赛等其他包先于身份包到达时不会消耗首次新增机会；
失联/身份过期时不发图元并清空刷新状态。发送队列没有客户端确认，因此周期新增仍用于恢复丢帧后的显示。旧来源未定义哨兵操作手客户端，
因此哨兵 ID 不自动推导地址；需要明确 `ui_receiver_id` 才能对指定客户端发送。

## 发射控制与许可

`shoot` 保留默认单例，也支持 Robot 持有独立第二实例。`init(info)` 绑定三台电机；
`start()` 幂等启动协程；`update(dt)` 是同一实现的一次协程迭代，可由模拟器直接调用。实际任务使用测量的 elapsed dt，首次和超过五个控制周期的间隔不推进斜坡。
重载 `init(info, left, right, trigger)` 接受 `motor_base&`，供设备绑定或无硬件模拟使用。

Robot 通过 `set_enabled(false)` 关闭实际绑定的三台执行器，并立即清空开火/摩擦轮/外部许可、斜坡与
堵转保持；`NoForce` 和回中阶段不得使能发射器。控制层每轮通过 `set_fire_permitted()` 写入当前云台
/视觉有效性。默认许可为 false。两套真实发射机构可以分别授权；旧哨兵配置共用三台发射电机，所以
默认只有一套发射实例，由两云台许可合成，不能重复初始化相同硬件。

摩擦轮仍以线速度 m/s 控制，左右符号相反。就绪条件为两轮速度幅值均 **大于或等于**
`friction_ready_speed`；该阈值必须大于 0 且不超过正的 `friction_max_speed`。这修复了 Hero 目标和阈值
同为 1.5 时，旧严格大于比较导致稳定跟踪却不能拨弹的边界错误，不改变硬件目标速度。拨弹明确调用 `set_angle_speed()`，目标 `trigger_speed`
为输出轴 rad/s，恢复旧代码中拨弹 PID 的角速度反馈语义；原来的 6/-2 不再误当作 m/s。
PID 参数仍需按秒制 dt 和硬件反馈重新标定。

拨弹需要同时满足：使能、当前外部许可、开火请求、摩擦轮开关与速度阈值、三电机在线、有限数值反馈、
不处于堵转暂停，及可选裁判许可。任意一台发射电机离线时本次更新将三台目标全部归零。堵转使用原始
电流幅值和输出轴 rpm，默认 `abs(current)>4000 && abs(rpm)<1` 暂停 50 毫秒，覆盖正反方向电流。

`enforce_referee: true` 时，必须有独立新鲜的比赛状态、机器人状态和剩余弹量；只有比赛阶段 4、HP>0、
发射电源许可为真且对应弹种数量>0 才允许拨弹。`bullet_caliber` 只接受 17/42，Hero 配置使用 42。
未收到、失联、数据过期、非比赛阶段均关闭拨弹。`enforce_referee: false` 是明确的无裁判调试策略，
仍受其余使能、遥控、云台/视觉与电机安全门限制。

这比旧逻辑“非比赛时跳过弹量检查”更保守；差异是显式配置策略。热量快照和弹速数据已迁移，但
预测热量、弹速闭环、按弹消耗估计及单发节拍没有可靠的旧实现，当前不提供这些保证。

## 无硬件验证

`tests/referee_protocol_tests.cpp` 使用从旧查表代码独立计算的 CRC/整帧 golden vector，覆盖所有拆包点、
坏 CRC/超长帧/噪声重同步、独立新鲜度、弹种字段、非法长度/浮点数、UI 位域/客户端映射、
身份晚到/过期恢复/身份切换时的首次新增，以及周期重建。
`tests/shoot_integration_tests.cpp` 用假电机执行真实 `shoot::update(dt)` 协程，检查实际下发目标与角/线速度
接口、精确正阈值/静止/非法阈值、禁用/许可/离线零输出、负电流堵转、NaN/Inf、双实例隔离、Hero 弹种、比赛阶段、HP 与电源门。
协议和发射测试均用直接 clang++ 编译运行通过；没有运行主程序、打开总线或进行上机测试。
